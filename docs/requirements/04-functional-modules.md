## 注册登录流程

```text
用户打开系统
  -> 选择登录或注册
  -> 系统校验账号密码
  -> 登录成功后写入 Session
  -> 根据是否已有角色跳转到仪表盘或角色创建页
```

规则：

- 用户名不可重复。
- 密码需要基础校验。
- 管理员和普通用户通过角色字段区分。
- 未登录访问用户页面时应跳转登录页。
- 普通用户不能访问后台页面。

## 角色创建流程

```text
首次登录
  -> 进入角色创建页
  -> 输入角色名、年级、专业类型
  -> 选择成长路线
  -> 系统创建 player_profile 和 player_attribute
  -> 进入仪表盘
```

创建后应展示：

- 角色昵称；
- 等级和经验；
- 当前属性；
- 推荐下一步行动。

## 仪表盘

仪表盘应是用户进入系统后的状态总览。

建议展示：

- 角色基本信息；
- 属性条；
- 当前周次；
- 最近事件结果；
- 任务摘要；
- 副本入口；
- 成长建议。

仪表盘不应变成复杂后台面板，用户应能快速知道“我现在状态如何、下一步去哪”。

## 校园地图流程

```text
用户进入地图
  -> 系统展示地点列表和属性摘要
  -> 用户选择地点
  -> 系统根据地点、事件池、属性条件和概率选择事件
  -> 用户进入事件页
  -> 用户选择处理方式
  -> 系统结算属性、经验和记录
  -> 返回结果页或地图
```

下一阶段建议：

- 同一地点支持多个事件随机触发；
- 属性影响事件触发概率；
- 某些事件需要前置标签；
- 地图页显示每个地点的风险/收益类型。

## 随机事件流程

```text
事件展示
  -> 用户阅读情境
  -> 用户选择一个选项
  -> 系统应用属性变化
  -> 写入事件记录
  -> 展示结果文案和属性变化
```

事件结果页应展示：

- 选择的选项；
- 结果描述；
- 属性变化；
- 经验变化；
- 是否触发隐藏标签或后续事件；
- 下一步入口。

## 任务系统流程

```text
用户创建任务
  -> 任务进入待完成
  -> 用户点击完成
  -> 系统增加经验和属性
  -> 任务状态变为已完成
```

Demo 阶段只要求基础可用。完整版本再支持：

- 任务模板；
- 任务推荐；
- 逾期处理；
- 任务统计；
- 任务和副本关联。

## 副本挑战流程

```text
用户选择副本
  -> 查看副本介绍和阶段目标
  -> 开始副本
  -> 系统加载当前阶段任务
  -> 用户完成系统预设的操作、选择或小游戏
  -> 系统计算阶段评价
  -> 更新属性、经验、总分、过程标签
  -> 推进到下一阶段
  -> 完成后生成最终评价
```

关键规则：

- 副本阶段不依赖用户自由填写完成内容。
- 当前阶段必须按顺序结算。
- 已完成副本不允许继续结算旧阶段。
- 完成后应显示最终评价和过程标签。
- 后续可支持重开副本或保留历史记录。

## 成就称号模块

推荐成就：

| 成就 | 条件 |
|---|---|
| 早八幸存者 | 完成 5 次早八相关事件且健康不低 |
| DDL 战神 | 在截止前完成多个高压任务 |
| 课设终结者 | 通关 Java 课设副本 |
| Bug 驯服师 | 多次正确完成 Bug 定位 |
| 运动续命大师 | 连续完成运动任务 |
| 社交悍匪 | 多次选择社交类高收益选项 |
| 粮食守护者 | 通关粮食守护者副本 |

称号可用于：

- 个人资料展示；
- 结局优先级判断；
- 排行榜；
- 答辩时展示系统激励机制。

## 成长报告模块

报告类型：

- 周报；
- 月报；
- 学期报告；
- 副本报告。

报告内容：

- 属性变化趋势；
- 完成任务数；
- 任务完成率；
- 常去地点；
- 常见事件；
- 副本通关情况；
- 成就称号；
- 系统建议。

报告不是当前重点，但后期课程设计报告和答辩展示会用到。

## 结局评价模块

结局生成优先级建议：

1. 特殊副本结局优先；
2. 极端属性结局其次；
3. 综合属性结局最后；
4. 若多个结局满足条件，选择优先级最高者。

推荐结局：

| 结局 | 条件方向 |
|---|---|
| 课设战神 | 技能高，Java 课设副本高评价 |
| DDL 幸存者 | 压力较高但最终完成关键任务 |
| 六边形工大学子 | 各项属性均衡 |
| 图书馆常驻民 | 学业高，图书馆事件多 |
| 运动续命大师 | 健康和自律高 |
| 预算崩盘人 | 金钱长期偏低 |
| 快乐摆烂人 | 压力低但自律和学业较低 |
| 粮食守护者 | 完成粮食守护者副本 |
