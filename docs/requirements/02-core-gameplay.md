# 02. Core Gameplay

## 核心循环

系统主循环如下：

```text
登录/注册
  -> 创建校园角色
  -> 查看属性状态
  -> 进入校园地图
  -> 选择地点或行动
  -> 触发随机事件或副本入口
  -> 做出选择/完成小游戏/接受属性判定
  -> 更新属性、经验、任务记录和过程标签
  -> 解锁成就、称号或结局
  -> 回到地图继续行动
```

这个循环需要保证每一步都有反馈。不要让用户只是“提交表单后回到列表”，而应让用户看到：

- 我刚刚做了什么选择；
- 这个选择改变了哪些属性；
- 这件事是否留下了后续影响；
- 下一步可以去哪里；
- 如果重玩，是否可能得到不同结果。

## 角色创建

用户首次登录后需要创建校园角色。

字段建议：

| 字段 | 说明 |
|---|---|
| 角色昵称 | 用户自定义 |
| 年级 | 大一、大二、大三、大四 |
| 专业类型 | 计算机类、食品类、机械类、经管类、通用等 |
| 成长路线 | 考研、就业、保研、竞赛、六边形、摆烂求生 |
| 当前周次 | 默认第 1 周 |
| 当前等级 | 默认 1 级 |
| 当前经验 | 默认 0 |

成长路线可以影响初始属性：

| 路线 | 属性倾向 |
|---|---|
| 考研路线 | 学业、自律更高，社交略低 |
| 就业路线 | 技能、社交更高，学业略低 |
| 竞赛路线 | 技能明显更高，压力略高 |
| 六边形路线 | 各项较均衡 |
| 摆烂求生路线 | 压力较低，但自律较低 |

## 属性系统

核心属性范围建议为 0-100。

| 属性 | 含义 | 高值影响 |
|---|---|---|
| 学业 | 课程学习、考试和理论基础 | 更容易通过学习类判定 |
| 健康 | 作息、运动、饮食 | 降低熬夜、体测、压力事件风险 |
| 金钱 | 生活费和消费状态 | 影响外卖、交通、社交、资料购买 |
| 社交 | 室友、同学、社团关系 | 影响求助、组队、活动事件 |
| 技能 | 编程、项目、实践能力 | 影响 Java 课设、Bug 定位、面试副本 |
| 压力 | DDL、考试、熬夜造成的负担 | 越高越危险，可能降低判定结果 |
| 自律 | 行动稳定性和任务完成习惯 | 影响复习、运动、任务推进 |

属性边界：

- 除经验外，属性最低 0，最高 100。
- 压力值越高代表状态越差。
- 健康低于 20 时可触发健康预警。
- 压力高于 80 时可触发崩溃/补救事件。
- 金钱低于 20 时可触发生活费危机。
- 学业低于 30 时可触发学业风险提示。

## 地图玩法

地图不是传统 GIS，而是“莲花街校区行动地图”。基础版用地点卡片即可，但需要有校园行动感。

基础地点：

| 地点 | 功能定位 | 事件方向 |
|---|---|---|
| 教学楼 | 学习、早八、课堂 | 点名、课堂提问、课程作业 |
| 图书馆 | 学业、自律 | 抢座、低电量、期末复习 |
| 宿舍 | 休息、社交、DDL | 室友开黑、断网、熬夜 |
| 食堂 | 健康、金钱 | 夜宵、排队、预算选择 |
| 操场 | 健康、自律 | 体测、跑步、运动任务 |
| 实验室 | 技能、副本 | Java 报错、数据库、课设 |
| 社团活动区 | 社交、成就 | 招新、活动、志愿服务 |
| 快递站 | 生活、随机支线 | 暴雨取件、排队、消费 |

地图页应展示：

- 当前角色属性摘要；
- 地点卡片；
- 地点类型和风险提示；
- 可能触发的事件类型；
- 核心副本入口，例如“Java 课设：DDL 前夜”；
- 最近一次事件或副本结果摘要。

## 随机事件

随机事件是地图玩法的主要内容来源。事件不应只是文字弹窗，而应有明确情境、选项和结算。

事件结构：

| 字段 | 说明 |
|---|---|
| 事件名称 | 例如“Java 代码报错” |
| 触发地点 | 实验室、图书馆等 |
| 事件类型 | 学习、生活、健康、社交、技能、金钱、特殊 |
| 情境描述 | 一段有画面感的故事 |
| 选项列表 | 2-4 个处理方式 |
| 属性变化 | 每个选项对应不同属性影响 |
| 经验奖励 | 事件完成后的经验变化 |
| 结果文案 | 用户选择后的反馈 |
| 触发条件 | 可选：属性条件、周次、概率、前置标签 |
| 视觉信息 | 可选：背景图、图标、主题色 |

事件选项设计原则：

1. 至少一个稳妥选项：收益中等，风险低。
2. 至少一个高风险选项：可能收益高，也可能增加压力或健康损失。
3. 至少一个生活化选项：体现大学生真实场景。
4. 选项不要只有“正确/错误”，应体现取舍。
5. 结果文案要解释为什么属性变化。

## 任务系统

任务系统用于承载日常目标，不应抢走副本的主要戏份。

任务类型：

| 类型 | 示例 |
|---|---|
| 学习任务 | 背单词、复习课程、完成作业 |
| 生活任务 | 打扫宿舍、整理桌面、买生活用品 |
| 健康任务 | 跑步、早睡、吃早餐 |
| 社交任务 | 参加社团、帮助同学、组队讨论 |
| 课设任务 | 需求分析、数据库设计、代码实现、答辩准备 |

任务字段：

| 字段 | 说明 |
|---|---|
| 任务名称 | 用户可见标题 |
| 任务类型 | 学习、健康、社交等 |
| 难度 | 简单、普通、困难 |
| 截止时间 | 可选 |
| 状态 | 待完成、已完成、已逾期、已放弃 |
| 经验奖励 | 完成后增加经验 |
| 属性影响 | 完成后调整属性 |
| 是否来自副本 | 区分普通任务和副本阶段任务 |

状态流转：

```text
待完成 -> 已完成
待完成 -> 已逾期
待完成 -> 已放弃
已逾期 -> 补救完成
```

Demo 阶段任务系统只需要支持基础创建、查看、完成和奖励。完整版本再增加模板、提醒、逾期惩罚和统计。
