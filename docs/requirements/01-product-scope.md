# 01. Product Scope

## 项目名称

推荐展示名称：

- 河南工业大学生存挑战
- HAUT Survivor
- 工大生存挑战

推荐课程设计题目：

> 基于 Java 的高校校园生存挑战与成长管理系统设计与实现：以河南工业大学为例

如果答辩希望更轻松，也可以使用：

> “工大生存挑战”：基于 Java 的校园生活模拟系统设计与实现

## 项目定位

HAUT Survivor 不是单纯的信息管理系统，也不是纯娱乐游戏，而是一个“校园生活模拟 + 成长管理 + 游戏化任务”的 Java Web 项目。

它的核心价值是把大学生日常场景转化为系统化流程：

- 校园地点：教学楼、图书馆、宿舍、食堂、操场、实验室、社团活动区、快递站。
- 生活事件：早八点名、DDL 逼近、图书馆抢座、Java 报错、夜宵诱惑、体测通知。
- 成长属性：学业、健康、金钱、社交、技能、压力、自律。
- 行为后果：选择不同方案后，属性、经验、压力和后续事件产生变化。
- 阶段挑战：通过副本把大型目标拆成情境任务、小游戏、判定和结局。

系统应既能满足课程设计中的“用户管理、数据库设计、业务流程、后台管理、数据持久化”等要求，也要让演示过程有明显的校园代入感和可玩性。

## 背景范围

项目背景设定为河南工业大学，当前优先使用莲花街校区。

已确认：

- 主校区场景：莲花街校区。
- 可使用真实地点名称，但后期再补充具体教学楼、食堂、宿舍区名称。
- 当前不要求真实 GIS 地图。
- 当前不要求真实照片或官方素材。
- 地点和事件可以参考真实校园生活，但不需要完全还原。

后续可补充：

- 具体教学楼名称。
- 具体食堂名称和常见餐饮场景。
- 宿舍区名称。
- 图书馆、实验室、快递站、社团活动区的真实称呼。
- 校园常见梗和答辩时可讲的趣味场景。

## 目标用户

主要用户：

| 用户 | 需求 |
|---|---|
| 普通学生 | 通过游戏化方式体验校园生活、管理任务、查看属性成长 |
| 课程设计答辩学生 | 展示一个有完整业务流程、数据库设计和创新点的 Java Web 项目 |
| 指导教师 | 评估系统的功能完整性、业务合理性、数据库设计和扩展能力 |
| 管理员 | 维护事件、选项、任务、副本、成就、结局等默认内容 |

## 用户痛点

| 痛点 | 系统回应 |
|---|---|
| 普通任务管理系统枯燥 | 使用地图、随机事件、副本和结局增强代入感 |
| 大学生生活选择复杂 | 用属性变化模拟学习、健康、社交、压力之间的取舍 |
| 课程设计容易变成普通 CRUD | 用情境任务、小游戏、过程标签和结局分支体现创新 |
| 演示过程容易单调 | 设计 5-10 分钟可试玩路线 |
| 后续内容难维护 | 事件、任务、副本、成就和结局尽量数据库化 |

## 当前开发决策

1. 技术栈以 Spring Boot + MyBatis-Plus + MySQL + Thymeleaf 为主。
2. 项目分为 Demo 基础版和完整版两个阶段推进。
3. 当前优先完成可以演示的学生端主流程。
4. 管理员后台采用渐进式实现，不应一开始被大量 CRUD 拖慢。
5. Demo 需要有可玩性，不能只是点按钮看表格。
6. 课程设计报告后期单独整理，当前以系统实现和需求拆解为主。

## 项目边界

当前不做：

- 大型 3D 游戏地图。
- 真实 GPS 定位。
- 真实教务系统对接。
- 真实支付。
- 强依赖 AI 大模型。
- 复杂多人在线实时玩法。

允许做轻量游戏化：

- 地点卡片式地图。
- 情境选择。
- 随机事件。
- 属性判定。
- 小测或小游戏。
- 过程标签。
- 多结局。
- 成就称号。

## 成功标准

Demo 成功不是“页面都能打开”，而是满足以下体验：

1. 用户能在 5-10 分钟内走完完整体验。
2. 玩家能看到自己的选择改变属性和后续结果。
3. 至少一个副本有阶段目标、小游戏和最终评价。
4. 页面有校园氛围，不全是白底表格。
5. 答辩时能讲出系统的业务逻辑、数据库设计和创新点。
