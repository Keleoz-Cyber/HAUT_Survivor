# 09. Semester Simulation Design

本文档定义 HAUT Survivor 后续升级方向：从“校园地图 + 事件 + 副本 Demo”升级为“周回合制大学生养成模拟器”。

核心目标：

> 让玩家在一个压缩学期中，用有限行动次数经营自己的学习、健康、社交、组织、项目、金钱和精神状态，形成独特的大学路线和多结局。

这份设计比传统功能需求更偏玩法设计。后续编码 AI 应以本文档作为“下一阶段产品方向”，但实现时仍要分阶段推进，不要一次性做完所有内容。

---

## 1. 核心体验

### 1.1 从管理系统到大学生模拟器

当前系统已经能完成：

```text
登录 -> 创建角色 -> 地图 -> 事件 -> 副本 -> 结算
```

后续应升级为：

```text
创建角色 -> 选择成长路线 -> 每周规划行动
  -> 学习 / 社交 / 组织 / 探索 / 副本 / 恢复
  -> 触发随机事件和隐藏机会
  -> 积累属性、关系、声望和过程标签
  -> 期中/期末/课设/组织换届等关键节点
  -> 学期结算和路线结局
```

玩家感受应类似：

- “这周只有 4 次行动，我该先补 Java，还是去社团面试？”
- “压力太高了，再熬夜可能出事，但 DDL 快到了。”
- “我多探索实验室，终于解锁老师项目组了。”
- “我加入学生会以后，社交涨了，但时间被活动吃掉了。”
- “这次用了 AI 辅助课设，效率高了，但答辩可能被追问。”

### 1.2 设计关键词

- 周回合制；
- 有限行动次数；
- 校园探索；
- 组织成长；
- 关系和搭子；
- 随机事件；
- 当前大学生生活元素；
- 多路线结局；
- 可演示、可扩展、可配置。

## 2. 周回合制主循环

### 2.1 学期结构

建议一局 Demo 使用压缩学期：

| 版本 | 周数 | 每周行动次数 | 适用 |
|---|---:|---:|---|
| Demo 版 | 4 周 | 4 次 | 快速演示 |
| 标准版 | 8 周 | 4 次 | 较完整体验 |
| 完整版 | 16 周 | 5 次 | 接近真实学期 |

建议先实现 Demo 版 4 周循环，避免开发量失控。

### 2.2 每周流程

```text
周开始
  -> 展示本周主题和随机提示
  -> 玩家拥有固定行动点
  -> 玩家选择行动
  -> 每次行动消耗 1 点
  -> 行动触发事件、属性变化或副本推进
  -> 行动点耗尽
  -> 周结算
  -> 检查关键节点、组织活动、DDL、考试、健康风险
  -> 进入下一周
```

### 2.3 行动点

行动点是养成策略感的核心。

建议字段：

| 字段 | 说明 |
|---|---|
| current_week | 当前周次 |
| action_points | 本周剩余行动点 |
| max_action_points | 每周最大行动点 |
| semester_phase | 学期阶段：early/mid/final |
| week_theme | 本周主题，例如“社团招新周”“期中预警”“DDL 高压周” |

行动点规则：

- 每周开始恢复到最大行动点；
- 普通行动消耗 1 点；
- 部分重要副本行动消耗 2 点；
- 健康过低可能减少行动点；
- 社交关系或组织加成可能增加行动点；
- 压力过高可能触发强制休息或负面事件。

### 2.4 行动类别

| 行动 | 主要影响 | 可能触发 |
|---|---|---|
| 学习 | 学业、自律、压力 | 课堂、图书馆、考试、资料整理 |
| 写代码/做项目 | 技能、压力、课设进度 | Java Bug、数据库、AI 辅助、答辩 |
| 锻炼 | 健康、自律、压力 | 体测、跑步搭子、操场事件 |
| 休息 | 健康、压力 | 宿舍、夜宵、室友关系 |
| 社交 | 社交、人脉、声望 | 搭子、社团、学生会、班级事件 |
| 组织活动 | 组织贡献、声望、关系 | 社团任务、学生会活动、竞选 |
| 探索地点 | 探索度、隐藏事件 | 隐藏地点、特殊 NPC、副本入口 |
| 推进副本 | 副本进度、关键标签 | Java 课设、期末、竞赛、面试 |
| 兼职/副业 | 金钱、压力、技能 | 自媒体、二手交易、校内兼职 |

## 3. 组织系统

组织系统用于承载大学生活中的“身份路线”。它能让玩家不只是提高属性，还能形成不同人生轨迹。

### 3.1 组织类型

| 组织 | 定位 | 核心收益 | 风险 |
|---|---|---|---|
| 学生会 | 活动、组织、人脉 | 社交、声望、组织贡献 | 占用时间、压力增加 |
| 社团 | 兴趣和社交 | 社交、灵感、特殊事件 | 学业时间减少 |
| 实验室小组 | 项目和技能 | 技能、老师关系、项目进度 | 压力、DDL |
| 竞赛队 | 算法/项目竞赛 | 技能、声望、成就 | 高压力、健康下降 |
| 志愿组织 | 公益和校园活动 | 社交、声望、自律 | 时间冲突 |
| 班委/课代表 | 班级事务 | 老师关系、声望 | 杂事多、压力增加 |
| 创业/自媒体小队 | 当代大学生副业 | 金钱、社交、灵感 | 风险、时间不稳定 |

### 3.2 组织成员状态

每个组织对用户有状态：

| 状态 | 说明 |
|---|---|
| locked | 未解锁 |
| discovered | 已发现但未加入 |
| applied | 已报名/面试中 |
| member | 普通成员 |
| core_member | 骨干成员 |
| leader | 负责人/部长/队长 |
| retired | 已退出或换届结束 |

### 3.3 组织成长

组织内成长不应只是数值 +1，而应有阶段事件。

示例：学生会路线

```text
第 1 周：社团招新摊位发现学生会
第 2 周：面试，考察社交和自律
第 3 周：活动救火，选择扛活还是划水
第 4 周：获得干事身份
第 6 周：晚会排练冲突，影响学习和健康
第 8 周：竞选部长，综合声望和贡献判定
```

示例：实验室小组路线

```text
探索实验室 -> 遇到老师项目组缺人
  -> 技能值和自律值达到要求可加入
  -> 每周可推进项目
  -> 随机触发接口崩溃、论文格式、数据清洗、答辩展示
  -> 最终解锁“实验室编外研究员”或“PPT 比代码先跑”结局
```

### 3.4 组织数据建议

组织表：

| 字段 | 说明 |
|---|---|
| organization_name | 组织名称 |
| organization_type | 社团、学生会、实验室、竞赛队等 |
| description | 介绍 |
| unlock_condition | 解锁条件 |
| recommended_attribute | 推荐属性 |
| weekly_cost | 每周活动消耗 |
| visual_theme | 视觉主题 |

用户组织关系表：

| 字段 | 说明 |
|---|---|
| user_id | 用户 |
| organization_id | 组织 |
| membership_status | 当前状态 |
| position_name | 职位 |
| contribution | 贡献值 |
| reputation | 组织内声望 |
| relationship_bonus | 组织关系加成 |
| join_week | 加入周次 |

## 4. 探索系统

探索系统用于让地图变得有发现感，不再只是地点菜单。

### 4.1 地点探索度

每个地点有探索度：

| 探索度 | 效果 |
|---:|---|
| 0 | 未探索，仅显示基础描述 |
| 20 | 解锁普通事件池 |
| 40 | 解锁隐藏地点或 NPC |
| 60 | 解锁组织入口或支线 |
| 80 | 解锁特殊副本或高收益事件 |
| 100 | 解锁地点称号或隐藏结局条件 |

### 4.2 地点隐藏内容

| 地点 | 探索发现 |
|---|---|
| 图书馆 | 隐藏自习角、考研学长、低电量危机、复习排序小游戏 |
| 实验室 | 老师项目组、竞赛队、AI 工具争议、Bug 定位副本 |
| 食堂 | 隐藏窗口、夜宵支线、预算危机、粮食守护者副本 |
| 宿舍 | 室友关系线、断网事件、夜聊、卫生检查 |
| 操场 | 跑步搭子、体测节奏条、健康恢复事件 |
| 社团区 | 社团招新、学生会面试、活动救火 |
| 快递站 | 暴雨取件、二手交易、神秘包裹 |

### 4.3 探索随机性

探索不是每次固定收益。

可能结果：

- 发现新事件；
- 增加地点探索度；
- 触发普通随机事件；
- 解锁组织；
- 遇到 NPC；
- 什么也没发现，但压力下降；
- 翻车，例如浪费时间或增加疲劳。

探索结算应受以下因素影响：

- 当前地点探索度；
- 社交或技能属性；
- 当前周次；
- 是否已有相关组织；
- 随机数；
- 压力和健康状态。

## 5. 关系与搭子系统

大学生模拟器不应只有属性，还应有关系。

### 5.1 关系类型

| 关系 | 作用 |
|---|---|
| 室友 | 宿舍事件、开黑、夜聊、互相帮忙 |
| 同班同学 | 组队、作业、课堂事件 |
| 学长学姐 | 组织、竞赛、实习建议 |
| 老师 | 课设、实验室、推荐机会 |
| 搭子 | 自习搭子、饭搭子、运动搭子 |

### 5.2 搭子玩法

搭子是当代大学生生活里很有辨识度的元素，可以作为轻量关系系统。

搭子类型：

| 搭子 | 加成 | 风险 |
|---|---|---|
| 自习搭子 | 学业、自律提升 | 对方摆烂会影响效率 |
| 饭搭子 | 压力下降、社交提升 | 金钱消耗 |
| 运动搭子 | 健康、自律提升 | 天气和体力影响 |
| 课设搭子 | 技能和项目进度提升 | 分工不均可能触发冲突 |
| 摆烂搭子 | 压力下降 | 学业和自律下降 |

### 5.3 关系事件

示例：

- 室友邀请开黑，但明天早八；
- 自习搭子突然鸽了；
- 学长推荐你进项目组；
- 老师提醒你的数据库设计不够规范；
- 饭搭子发现隐藏窗口；
- 课设搭子把代码写崩了。

关系不必一开始做完整 NPC 系统。Demo 可先做“关系标签 + 关系值 + 事件加成”。

## 6. 当代校园元素与副本创意

内容要有当下感，但要控制表达，不要让课程设计显得过度玩梗。

### 6.1 可用流行元素

| 元素 | 玩法化方式 |
|---|---|
| AI 工具辅助 | 提升效率，但答辩追问风险上升 |
| 校园墙投稿 | 社交、声望、随机事件 |
| 搭子文化 | 关系系统和行动加成 |
| MBTI/性格梗 | 作为社交事件文案，不做真实心理判断 |
| 短视频/自媒体 | 副业路线，金钱和声望收益，时间风险 |
| 蓝桥杯/挑战杯/互联网+ | 竞赛副本 |
| 大创项目 | 项目、PPT、组队、老师关系 |
| 考研/考公/就业 | 后期路线分化 |
| AI 查重/论文格式 | 毕设或报告副本 |
| 外卖/拼单/二手交易 | 金钱和生活事件 |
| 反诈/网络安全 | 特殊校园事件 |

### 6.2 副本库扩展

#### 1. Java 课设：DDL 前夜

当前已实现基础版，后续继续强化 Bug 定位小游戏和答辩追问。

可加入：

- AI 生成代码争议；
- Git 冲突；
- 端口占用；
- 数据库字段错位；
- 答辩老师追问“你这个表为什么这么设计？”

#### 2. 图书馆席位战争

主题：期末周、复习、抢座、自律。

阶段：

1. 制定复习计划；
2. 抢座；
3. 复习优先级排序；
4. 低电量危机；
5. 考前小测；
6. 期末结算。

小游戏：复习优先级排序。

#### 3. 社团换届风暴

主题：组织、社交、活动救火。

阶段：

1. 报名社团；
2. 面试；
3. 活动救火；
4. 人际冲突；
5. 竞选部长；
6. 换届结算。

结局：

- 社团风云人物；
- 活动工具人；
- 体面退社；
- PPT 苦力王。

#### 4. 学生会晚会救火现场

主题：学生会、组织能力、突发事件。

阶段：

1. 接到活动任务；
2. 物资预算；
3. 节目临时缺人；
4. 现场设备故障；
5. 老师检查；
6. 活动结算。

小游戏：资源分配 / 应急选择。

#### 5. 蓝桥杯突击：算法修仙七日谈

主题：竞赛、算法、压力。

阶段：

1. 报名；
2. 刷题计划；
3. 动态规划噩梦；
4. 模拟赛；
5. 赛前心态；
6. 比赛结算。

小游戏：题型优先级选择 / 快问快答。

#### 6. 大创项目：PPT 比代码先跑

主题：项目、组队、汇报。

阶段：

1. 组队；
2. 选题；
3. 分工；
4. 原型开发；
5. PPT 包装；
6. 中期检查。

随机事件：

- 队友失联；
- 老师说“再加一点创新点”；
- PPT 很好看但功能没跑起来；
- 功能跑起来但没人会讲。

#### 7. 实习面试：八股文生存战

主题：就业、技能、表达。

阶段：

1. 简历修改；
2. Java 基础；
3. 项目介绍；
4. HR 问答；
5. 技术追问；
6. Offer/复盘。

小游戏：面试快问快答。

#### 8. 毕设开题：导师灵魂三问

主题：毕业设计、研究方向、论文。

阶段：

1. 选题；
2. 查文献；
3. 开题 PPT；
4. 导师追问；
5. 修改方案；
6. 开题结算。

可作为完整版后期内容，不建议 Demo 先做。

## 7. 多路线结局设计

结局不应只分好坏，而应像路线画像。

### 7.1 学业/技能线

| 结局 | 条件方向 |
|---|---|
| 课设战神 | Java 课设高分，技能高 |
| 实验室编外研究员 | 实验室探索高，老师关系好，项目进度高 |
| 竞赛修仙者 | 竞赛队贡献高，技能高，健康可能偏低 |
| 图书馆常驻民 | 图书馆探索高，学业高，自律高 |
| 八股文幸存者 | 面试副本通关，就业路线推进 |

### 7.2 组织/社交线

| 结局 | 条件方向 |
|---|---|
| 社团风云人物 | 社团职位高，声望高 |
| 学生会活动发动机 | 学生会贡献高，活动成功多 |
| 校园社交王 | 社交高，搭子关系多 |
| 班级稳定器 | 班委路线高贡献 |
| 活动工具人 | 组织贡献高但压力过高，学习受损 |

### 7.3 生活/状态线

| 结局 | 条件方向 |
|---|---|
| 六边形工大学子 | 各项均衡 |
| DDL 幸存者 | 高压力但关键任务完成 |
| 快乐摆烂人 | 压力低，自律低，学业普通 |
| 预算崩盘但精神富足 | 金钱低，社交或快乐路线高 |
| 运动续命大师 | 健康和自律高 |
| 夜宵哲学家 | 食堂事件多，压力控制好但健康一般 |

### 7.4 特殊隐藏结局

| 结局 | 条件方向 |
|---|---|
| PPT 比代码先跑 | 大创或课设中汇报强、功能弱 |
| AI 辅助大师 | 多次使用 AI 工具并成功应对追问 |
| 端口占用受害者 | 多次在 Java 副本中遇到启动问题 |
| 校园墙传说 | 校园墙事件多且声望高 |
| 隐藏窗口发现者 | 食堂探索度高 |

## 8. 随机性设计

随机性要让游戏有变化，但不能让玩家觉得不可控。

### 8.1 随机事件来源

| 来源 | 示例 |
|---|---|
| 地点 | 图书馆抢座、食堂夜宵 |
| 周主题 | 社团招新周、期中周、DDL 周 |
| 属性状态 | 压力过高触发崩溃事件 |
| 组织身份 | 学生会活动、社团换届 |
| 探索度 | 隐藏地点或 NPC |
| 关系 | 搭子邀约、室友求助 |
| 副本标签 | 数据库设计混乱导致 Bug 事件 |

### 8.2 可控随机

建议采用“权重随机”：

- 地点决定事件池；
- 周次决定事件可用性；
- 属性影响事件权重；
- 已触发事件降低重复概率；
- 高探索度提升隐藏事件概率；
- 关键主线事件可强制出现。

### 8.3 翻车与惊喜

同一行动可以有小概率不同结果：

| 行动 | 普通结果 | 惊喜 | 翻车 |
|---|---|---|---|
| 图书馆学习 | 学业增加 | 遇到自习搭子 | 没抢到座 |
| 实验室写代码 | 技能增加 | 老师项目组招人 | Bug 爆炸 |
| 社团活动 | 社交增加 | 被学长推荐 | 活动临时加班 |
| 食堂吃饭 | 健康恢复 | 发现隐藏窗口 | 生活费下降过多 |
| 操场跑步 | 健康增加 | 遇到运动搭子 | 下雨中断 |

## 9. Demo 优先级

### 9.1 第一阶段：周回合制壳子

目标：先让系统从“无限点地图”变成“每周有限行动”。

最小实现：

- 当前周次；
- 本周剩余行动点；
- 行动后扣点；
- 行动点用完后进入下一周；
- 仪表盘显示周次和行动点；
- 地图行动消耗行动点。

### 9.2 第二阶段：组织系统最小版

目标：先做两个组织。

建议先做：

1. 学生会；
2. 实验室小组。

最小实现：

- 组织列表；
- 发现组织；
- 加入组织；
- 每周参加组织活动；
- 贡献值；
- 组织事件；
- 简单职位变化。

### 9.3 第三阶段：探索系统最小版

目标：地点有探索度。

建议先做：

- 图书馆；
- 实验室；
- 食堂；
- 社团活动区。

最小实现：

- 用户地点探索记录；
- 探索行动；
- 探索度增加；
- 探索度解锁隐藏事件；
- 地图页显示探索进度。

### 9.4 第四阶段：Bug 定位小游戏

目标：把 Java 课设第三阶段升级为小游戏。

最小实现：

- 后端题库；
- 前端展示 Bug 现象；
- 用户选择原因；
- 后端结算；
- 受技能、压力、`schema_clear/schema_mist` 影响；
- 写入阶段记录。

### 9.5 第五阶段：学期结局

目标：Demo 4 周结束后生成路线画像。

最小结局：

- 课设战神；
- 图书馆常驻民；
- 社团风云人物；
- 实验室编外研究员；
- DDL 幸存者；
- 快乐摆烂人；
- 六边形工大学子。

## 10. 编码 AI 分阶段实施建议

如果把任务交给编码 AI，不要一次让它实现所有系统。建议按以下顺序：

### 实施包 1：周回合制核心

交付：

- 数据库增加周次和行动点相关字段或表；
- 仪表盘展示当前周和行动点；
- 地图行动消耗行动点；
- 行动点耗尽后可进入下一周；
- 测试覆盖行动点扣减和周推进。

### 实施包 2：组织系统 MVP

交付：

- organization 表；
- user_organization 表；
- 组织列表页；
- 加入组织；
- 参加组织活动；
- 贡献值和属性结算；
- 学生会、实验室小组 seed data。

### 实施包 3：探索系统 MVP

交付：

- user_location_exploration 表；
- 探索行动；
- 探索度展示；
- 探索解锁事件；
- 图书馆和实验室优先。

### 实施包 4：Bug 定位小游戏

交付：

- Bug 题库；
- 副本第三阶段小游戏页面；
- 后端结算规则；
- 过程标签影响；
- 测试和 HTTP 冒烟。

### 实施包 5：学期结局和图鉴

交付：

- semester_ending 规则；
- 用户学期结算；
- 结局展示；
- 已解锁结局记录；
- 重玩提示。

## 11. 对课程设计的解释方式

答辩时可以这样解释升级后的系统：

> 本系统不是传统学生信息管理系统，而是面向大学生的校园成长模拟器。系统用周回合制模拟大学学期，用行动点表达时间资源有限，用属性系统表达学习、健康、社交、技能和压力之间的取舍，用组织、探索、随机事件和副本模拟大学生活中的关键选择，最终根据玩家行为生成不同成长路线和结局。

可以强调：

1. 有明确业务建模：用户、属性、地点、事件、组织、副本、结局；
2. 有数据库设计价值：多表关系、记录历史、规则结算；
3. 有创新点：周回合制、组织成长、探索度、随机事件、过程标签；
4. 有可演示性：4 周压缩学期能在答辩现场走完；
5. 有扩展性：可继续增加副本、组织、事件和结局。
