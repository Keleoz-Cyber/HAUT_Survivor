# 07. Roadmap And Acceptance

## 阶段划分

项目分为三个阶段：

1. Demo 基础版；
2. 完整版；
3. 加强版。

当前项目已经完成 Demo 基础版的大部分功能，并完成一轮可玩性增强。后续应继续围绕“可玩性和展示效果”推进，而不是马上扩大量后台 CRUD。

## Demo 基础版目标

Demo 基础版目标不是只做一个能点通的系统，而是完成一段可以顺利答辩演示、且有基础可玩性的短流程体验。

用户应能在 5-10 分钟内体验：

1. 登录和创建校园角色；
2. 查看属性；
3. 进入莲花街校区地图；
4. 触发校园事件；
5. 做出选择并看到属性变化；
6. 进入 Java 课设副本；
7. 完成至少一个小游戏或小测；
8. 获得副本结算和最终评价；
9. 管理员能维护基础事件内容。

## Demo 基础版必备功能

| 功能 | 要求 |
|---|---|
| 注册登录 | 支持普通用户和管理员 |
| 角色创建 | 创建学生角色并初始化属性 |
| 属性面板 | 展示学业、健康、金钱、社交、技能、压力、自律 |
| 校园地图 | 至少 8 个莲花街校区通用地点 |
| 随机事件 | 至少 8-12 个默认事件 |
| 事件选项 | 每个事件 2-3 个选项，能改变属性 |
| 基础任务 | 支持创建、查看、完成任务 |
| 核心副本 | Java 课设：DDL 前夜 |
| 小游戏 | 至少一个轻量小游戏或小测 |
| 副本结算 | 阶段评价、总分、最终评价 |
| 视觉基础 | 地图、事件、副本页不能全是白底表格 |
| 管理后台 | 至少支持事件和事件选项管理 |
| 数据持久化 | 数据保存到 MySQL |

## 当前 Demo 演示路线

```text
登录 student/student123
  -> 创建或进入校园角色
  -> 打开校园地图
  -> 点击实验室触发剧情事件
  -> 选择事件处理方式并查看属性变化
  -> 进入“Java 课设：DDL 前夜”
  -> 完成“需求风暴”
  -> 完成“数据库拼图”
  -> 完成“Bug 暴走”
  -> 查看最终评价和过程标签
```

## 推荐下一轮开发目标

下一轮优先级：

1. 地图事件随机化；
2. Bug 暴走升级为 Bug 定位小游戏；
3. 增加地点和副本视觉背景；
4. 增加结局图鉴和重玩提示；
5. 扩充事件文案和副本内容。

不建议下一轮优先做：

- 大量管理员后台 CRUD；
- 排行榜；
- 成长报告图表；
- 多校区地图；
- 复杂权限系统；
- 前后端分离重构。

原因：当前最大短板是可玩性和展示吸引力，不是管理功能。

## 完整版目标

完整版在 Demo 基础上增加：

1. 多个主题副本；
2. 成就称号；
3. 结局评价；
4. 成长报告；
5. 统计图表；
6. 更完整后台；
7. 更多默认内容；
8. 可配置图片、任务类型、小游戏和结算规则。

## 完整版功能清单

| 模块 | 完整版要求 |
|---|---|
| 副本挑战 | 支持期末周、Java 课设、体测、粮食守护者、面试 |
| 副本任务 | 每个副本有任务目标、任务类型、情境、完成方式、结算规则 |
| 成就称号 | 根据任务、事件、副本结果触发 |
| 结局评价 | 根据属性、任务、成就、副本生成 |
| 成长报告 | 周报、月报、学期报告、副本报告 |
| 数据统计 | 属性趋势、任务完成率、事件触发次数 |
| 管理后台 | 覆盖地点、事件、任务模板、副本、成就、结局规则 |
| 内容素材 | 更多事件、副本、成就、结局和视觉素材 |

## 加强版方向

加强版可选：

1. 排行榜；
2. 结局图鉴；
3. 多校区地图；
4. 专业路线差异化；
5. 连续剧情事件；
6. 存档导出；
7. 主题皮肤；
8. 多人宿舍小队挑战。

## 基础验收标准

基础验收至少满足：

1. 用户可以注册登录；
2. 用户可以创建角色；
3. 用户可以查看属性；
4. 用户可以选择地点；
5. 系统可以触发事件；
6. 用户选择事件选项后属性发生变化；
7. 用户可以创建和完成任务；
8. 用户可以体验至少一个简化副本；
9. Demo 中至少出现一个小游戏、小测或属性判定关卡；
10. 地图页、事件页或副本页有基础视觉素材；
11. 管理员可以管理事件；
12. 数据可以保存到数据库；
13. 系统可以正常演示完整流程。

## 完整验收标准

完整验收应满足：

1. 支持多个副本；
2. 支持成就称号；
3. 支持结局评价；
4. 支持成长报告；
5. 支持后台管理任务、副本、成就；
6. 支持统计图表；
7. 界面清晰并具有校园视觉风格；
8. 副本和事件具备可配置图片、任务类型、小游戏和结算规则；
9. 项目结构清晰，测试覆盖关键业务流程。

## 答辩表述建议

答辩时不要只说“我做了一个游戏”，建议说：

> 本项目面向大学生群体，以河南工业大学校园生活为背景，将学习、生活、社交、健康和技能成长等内容进行游戏化建模。系统通过校园地点、随机事件、任务挑战、副本机制、属性成长、成就称号和结局评价等功能，引导学生在模拟场景中体验大学生活中的选择与取舍，从而提升学生自我管理意识和学习生活规划能力。

可突出三点：

1. 它不是传统学生管理系统，而是校园生活模拟与成长管理系统；
2. 它不是纯娱乐游戏，而是游戏化激励下的任务管理和成长记录；
3. 事件、任务、副本和成就可由后台配置，系统具有扩展性。
