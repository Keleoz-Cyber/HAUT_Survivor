# 10. UI 2.0 游戏化界面重构需求

## 1. 重构背景

当前 HAUT Survivor 的核心玩法已经基本闭环：角色创建、行动点、校园地图、事件选择、探索、组织、副本、结局和新学期重开都已可运行。

但当前界面仍然偏“Web 管理系统”：

- 顶部导航像后台系统菜单；
- 仪表盘像数据面板；
- 地图仍偏地点卡片列表；
- 副本列表和副本阶段仍像任务清单；
- 事件页虽然有情境文字，但缺少演出感；
- 结局页像结果详情，不像学期回忆；
- 页面之间缺少统一的游戏主循环氛围。

UI 2.0 的目标不是简单美化，而是把玩家端从“系统页面”改造成“大学生人生模拟器界面”。

## 2. 总体设计方向

推荐方向：**人生模拟器 + 视觉小说事件 + 校园手机界面**。

参考感受：

- 《中国式家长》的成长模拟和结算反馈；
- 人生模拟器类游戏的周回合制选择；
- 视觉小说的情境演出和选择按钮；
- 大学校园 App / 手机桌面的入口组织；
- 河南工业大学莲花街校区的现实地点氛围。

不要做成：

- SaaS 仪表盘；
- 后台管理系统；
- 纯暗黑科幻；
- 过度二次元；
- 大型 3D 地图；
- 复杂动画堆叠。

Demo 阶段应该优先做到：**一眼看上去像游戏，操作流程像大学生活模拟，反馈清楚，页面有记忆点。**

## 3. UI 2.0 范围

### 3.1 第一阶段必须重做

玩家核心流程页面：

| 页面 | 当前问题 | UI 2.0 目标 |
|---|---|---|
| `dashboard/index.html` | 像仪表盘 | 改成寝室/手机主界面 |
| `map/index.html` | 像地点卡片列表 | 改成莲花街校区行动地图 |
| `map/event.html` | 事件演出不足 | 改成视觉小说式事件页 |
| `exploration/index.html` | 像探索列表 | 改成校园巡游/踩点界面 |
| `exploration/result.html` | 反馈偏普通 | 改成探索发现页 |
| `organization/index.html` | 像组织列表 | 改成社团招新/组织广场 |
| `organization/detail.html` | 像详情页 | 改成组织活动场景 |
| `dungeon/index.html` | 像副本列表 | 改成挑战选择界面 |
| `dungeon/detail.html` | 氛围不足 | 改成副本封面页 |
| `dungeon/play.html` | 任务感仍强 | 改成关卡挑战页 |
| `dungeon/result.html` | 结算普通 | 改成阶段战报 |
| `ending/index.html` | 像结果页 | 改成学期回忆报告 |
| `fragments/layout.html` | 顶部导航后台感强 | 改成游戏 HUD / 手机底栏 |
| `app.css` | 风格不统一 | 建立统一游戏视觉系统 |

### 3.2 第一阶段暂不重做

以下页面只做基本兼容，不作为视觉重点：

- 登录页；
- 注册页；
- 角色创建页；
- 普通任务页；
- 管理员事件管理页。

管理员页面可以继续保持朴素，因为它不是玩家体验核心。

## 4. 统一视觉语言

### 4.1 基础氛围

整体氛围应该是“工大校园生活模拟”，不是纯幻想游戏。

建议视觉关键词：

- 晚自习；
- 寝室台灯；
- 食堂窗口；
- 操场跑道；
- 图书馆座位；
- 实验室代码屏幕；
- 社团招新海报；
- 手机消息提醒；
- DDL 压迫感；
- 学期回忆。

### 4.2 色彩原则

避免全站单一蓝紫渐变，也避免全白后台。

建议建立 5 组场景色：

| 场景 | 色彩方向 | 用途 |
|---|---|---|
| 寝室主界面 | 深靛蓝 + 台灯暖黄 | 主界面、夜间状态 |
| 校园地图 | 草地绿 + 路灯黄 + 建筑灰 | 地图和地点节点 |
| 学习/实验室 | 深蓝黑 + 终端绿 + 代码青 | Java 课设、副本 |
| 社交/组织 | 海报红 + 活力橙 + 奶白 | 社团、学生会 |
| 体测/操场 | 跑道红 + 草坪绿 + 天空蓝 | 体测副本、健康事件 |

压力相关反馈仍使用红色或警告色；压力下降应使用正向颜色。

### 4.3 字体和排版

不引入复杂字体依赖，优先使用系统中文字体。

排版要求：

- 大标题用于场景名和事件标题；
- 角色状态、行动点、周次应像 HUD；
- 选项按钮要大、清晰、有行动语气；
- 不要大段说明文字堆叠；
- 移动端文本不能挤出按钮或卡片；
- 页面第一屏必须能看出当前场景。

### 4.4 图片和视觉素材

短期不依赖版权图片。优先使用以下方式：

1. CSS 场景背景；
2. 伪元素纹理；
3. emoji / 图标；
4. 简单地点插画块；
5. 渐变叠加和光影；
6. 后续可替换为 AI 生成背景图。

要求：

- 每个核心页面必须有明显背景或场景氛围；
- 不要只用白底卡片；
- 地点和副本要有各自的视觉记忆点；
- 视觉不能遮挡文字和按钮。

## 5. 导航重构

### 5.1 当前问题

当前导航是传统顶部菜单：

```text
HAUT Survivor | 仪表盘 | 校园地图 | 副本 | 组织 | 探索 | 任务 | 退出
```

这会让玩家感觉进入了一个管理系统。

### 5.2 UI 2.0 方案

改为“游戏 HUD + 手机底栏”。

桌面端：

- 顶部只保留品牌、当前周次、行动点、压力状态、退出；
- 主入口放在页面内的手机桌面或底部 Dock；
- 不再把所有模块平铺在顶部导航。

移动端：

- 底部固定 4 个核心入口：
  - 寝室；
  - 地图；
  - 副本；
  - 组织。
- 探索可以作为地图内入口，不一定独立放导航。

建议文案：

| 旧文案 | 新文案 |
|---|---|
| 仪表盘 | 寝室 |
| 校园地图 | 去校园 |
| 副本 | 挑战 |
| 组织 | 社团 |
| 探索 | 踩点 |
| 任务 | 待办 |

## 6. 页面设计要求

### 6.1 寝室主界面

替代当前 `dashboard/index.html`。

定位：玩家每周开始和行动后回到的主界面。

画面感觉：

- 夜晚寝室；
- 桌面台灯；
- 电脑屏幕；
- 手机消息；
- 便利贴待办；
- 压力条像精神状态提醒。

必须展示：

- 玩家姓名、称号、成长路线；
- 当前学期第几周；
- 行动点；
- 7 个属性；
- 压力预警；
- 推荐行动；
- 学期结束入口；
- 最近一次结果提示，若后端暂无数据可先不做。

布局建议：

```text
[顶部 HUD：第 2 周 / 行动点 3/4 / 压力 42]

[寝室场景主区域]
  左：角色状态卡 / 今日心情
  中：手机桌面入口
  右：属性雷达或属性条

[底部：本周推荐行动 / DDL 提醒 / 副本入口]
```

交互要求：

- 行动点为 0 时，突出“结束本周”；
- 学期结束时，突出“查看学期回忆”；
- 属性不只显示数字，至少用条形表现。

### 6.2 莲花街校区行动地图

替代当前 `map/index.html`。

定位：玩家选择本次行动地点。

画面感觉：

- 不是真实精确地图，而是“校园行动棋盘”；
- 每个地点是一个可点击节点；
- 地点之间有路径、灯光或地图纹理；
- 中心突出“今天去哪儿续命？”。

地点建议：

| 地点 | 氛围 | 主要玩法倾向 |
|---|---|---|
| 教学楼 | 早八、点名、课堂 | 学业、压力 |
| 图书馆 | 座位、电量、自习 | 学业、自律、探索 |
| 宿舍 | 熬夜、室友、外卖 | 健康、压力、随机事件 |
| 食堂 | 排队、窗口、饭搭子 | 健康、社交 |
| 操场 | 跑步、体测、夜跑 | 健康、压力 |
| 实验室 | 代码、项目、导师 | 技能、学业、副本 |
| 社团区 | 海报、招新、活动 | 社交、组织 |
| 快递站 | 排队、包裹、雨天 | 随机、金钱、趣味 |

节点展示：

- 地点名；
- 氛围短句；
- 探索度；
- 可能影响的属性；
- 行动点消耗；
- “去这里”按钮。

地图页不要再像普通卡片网格。可以用 CSS Grid 做不规则节点布局。

### 6.3 事件演出页

替代当前 `map/event.html`。

定位：游戏感最强的页面之一。

页面结构：

```text
[场景背景：地点氛围]
[左上：地点 / 时间 / 氛围标签]
[中间：事件标题]
[正文：情境描述]
[角色状态小条：压力、行动点、关键属性]
[下方：选择按钮 2-3 个]
```

选项按钮要求：

- 不要只显示选项文本；
- 每个选项像一个行动决定；
- 可显示倾向标签，例如：
  - 稳妥；
  - 冒险；
  - 摆烂；
  - 社交；
  - 硬刚；
  - 求助；
  - 赌一把。

结果页要求：

- 显示一句有记忆点的结果反馈；
- 显示属性变化；
- 显示当前值；
- 提供“继续逛校园”和“回寝室”；
- 结果反馈要像事件结算，不像表单提交成功。

### 6.4 探索页

替代 `exploration/index.html` 和 `exploration/result.html`。

定位：不是“探索列表”，而是“在校园里踩点、发现隐藏东西”。

探索首页：

- 显示每个地点探索度；
- 高探索度地点出现“传闻”、“隐藏线索”、“组织入口”等提示；
- 可加入“本周传闻”区域。

探索结果页：

- 标题可以是“你在图书馆角落发现了……”；
- 展示探索度增加；
- 展示随机发现类型；
- 如果发现隐藏事件或组织，给出明显提示；
- 属性变化继续保留。

### 6.5 组织系统界面

替代 `organization/index.html` 和 `organization/detail.html`。

定位：社团招新广场 + 组织活动场景。

组织列表不应像表格或普通列表，应像一面“招新海报墙”。

组织卡片展示：

- 组织名称；
- 类型；
- 招新口号；
- 加入门槛；
- 当前关系；
- 本周可参加活动；
- 组织贡献。

组织详情页：

- 学生会：会议室、策划案、活动现场；
- 实验室：电脑、终端、导师任务；
- 篮球社：球场、训练、比赛；
- 活动结果要有不同文案和属性变化；
- 晋升时要有明显提示。

### 6.6 副本挑战界面

替代 `dungeon/index.html`、`dungeon/detail.html`、`dungeon/play.html`、`dungeon/result.html`。

定位：最能体现“可玩性”的模块。

副本列表页：

- 像挑战选择界面；
- 每个副本是一个封面；
- 显示难度、预计时间、推荐属性、奖励称号、完成状态。

副本详情页：

- 像挑战封面；
- 显示剧情简介；
- 显示阶段路线；
- 显示风险提示；
- 显示开始按钮。

副本进行页：

```text
[副本标题 / 当前阶段 2/3 / 进度条]
[场景描述]
[当前状态：分数、标签、关键属性]
[小游戏或选项操作区]
[阶段目标]
```

小游戏要求：

- 数据库拼图要更像“连线/关系板”，不要只是普通复选框；
- Bug 定位要像“错误控制台 + 线索选择”，不要像普通测验；
- 体测副本可以用节奏条或项目卡片表现。

副本结算页：

- 改名为“阶段战报”；
- 显示本阶段评价；
- 显示得分；
- 显示过程标签；
- 显示属性变化；
- 如果副本完成，显示最终评价和称号。

### 6.7 学期回忆报告

替代 `ending/index.html`。

定位：一次周目的收束。

页面感觉：

- 像游戏结算报告；
- 有“本学期关键词”；
- 有最终称号；
- 有属性快照；
- 有关键经历回顾；
- 有“再来一学期”。

建议结构：

```text
[学期结束]
[最终称号 / 结局图标 / 结局描述]
[属性快照]
[本学期经历：探索、组织、副本、隐藏事件]
[历史结局图鉴]
[重开新学期]
```

当前如果后端没有完整经历数据，可以先展示已有历史结局、属性、路线和副本记录。

## 7. 组件设计

建议在 `app.css` 中建立以下游戏 UI 组件：

| 组件 | 用途 |
|---|---|
| `.game-shell` | 玩家端整体背景和宽度 |
| `.game-hud` | 顶部状态栏 |
| `.game-dock` | 手机底部入口 |
| `.scene-panel` | 场景容器 |
| `.phone-home` | 寝室手机主入口 |
| `.stat-bar` | 属性条 |
| `.pressure-alert` | 压力提醒 |
| `.campus-map-v2` | 地图容器 |
| `.campus-node` | 地点节点 |
| `.vn-stage` | 视觉小说场景 |
| `.choice-card` | 事件选择 |
| `.result-burst` | 结果反馈 |
| `.dungeon-cover-v2` | 副本封面 |
| `.dungeon-progress` | 副本进度 |
| `.battle-report` | 阶段战报 |
| `.semester-report` | 学期报告 |

尽量不要在每个页面写大量内联样式。

## 8. 响应式要求

桌面端：

- 允许双栏或三栏；
- 地图可做不规则节点布局；
- 寝室页可以有主视觉区域。

移动端：

- 优先单列；
- 底部 Dock 固定；
- 选项按钮全宽；
- 地图节点改为纵向地点路线；
- 属性条不能挤压文字。

最低要求：

- 375px 宽度不横向滚动；
- 按钮文字不溢出；
- 事件选择可单手点击；
- 结算页信息不遮挡。

## 9. 文案风格

UI 文案要更像游戏，不要像系统。

示例：

| 系统感文案 | 游戏化文案 |
|---|---|
| 仪表盘 | 回到寝室 |
| 查看详情 | 掀开看看 |
| 执行任务 | 开始行动 |
| 提交选择 | 就这么办 |
| 结果 | 这次发生了什么 |
| 属性变化 | 状态变化 |
| 结束本周 | 熬过这一周 |
| 重开新学期 | 再来一学期 |
| 副本列表 | 挑战清单 |
| 组织详情 | 今天组织在忙什么 |

文案可以轻松、有梗，但不要过度网络烂梗。要适合大学生模拟器。

## 10. 验收标准

UI 2.0 第一阶段完成后，应满足：

1. 玩家端核心页面不再像后台管理系统；
2. 寝室、地图、事件、副本、结局各有不同视觉场景；
3. 导航更像游戏 HUD 或手机入口；
4. 事件选择有视觉小说式演出；
5. 副本挑战有阶段感和战报感；
6. 学期结束像周目结算；
7. 属性变化和当前值仍清楚可见；
8. 行动点、周次、压力状态在核心页面始终明显；
9. 移动端可用；
10. 现有后端功能和测试不应被破坏。

- 事件变成视觉小说式选择；

### 第三批：重做副本和结局

文件：

- `dungeon/index.html`
- `dungeon/detail.html`
- `dungeon/play.html`

- 副本变成挑战关卡；

1. fragments/layout.html
2. app.css
3. dashboard/index.html

第一批具体要求：
