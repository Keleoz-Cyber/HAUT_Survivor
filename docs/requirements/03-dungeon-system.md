# 03. Dungeon System

## 模块定位

副本是 HAUT Survivor 最能体现可玩性的模块。它不是一组普通任务清单，而是一段有目标、有压力、有阶段、有选择、有小游戏、有结算的短流程挑战。

基础版至少要完成一个 5-10 分钟可演示副本。推荐并当前已实现的核心副本是：

> Java 课设：DDL 前夜

## 副本基础结构

副本由以下部分组成：

| 内容 | 说明 |
|---|---|
| 副本名称 | 例如“Java 课设：DDL 前夜” |
| 副本主题 | 课设、期末、体测、粮食守护、面试 |
| 背景故事 | 用户为什么进入这个副本 |
| 推荐属性 | 例如技能、自律、学业 |
| 阶段任务 | 按顺序推进的任务链 |
| 任务类型 | 单选策略、小游戏、小测、属性判定、普通确认、关键任务 |
| 结算规则 | 每个阶段如何给分、加经验、改属性 |
| 过程标签 | 记录关键选择和后果 |
| 结局评价 | 副本完成后生成最终评价 |

## 情境驱动式任务机制

副本阶段任务原则上由系统预设，避免让用户自由输入完成内容。原因：

- 自由输入难以校验是否真实完成；
- 自由输入难以判断完成质量；
- 自由输入不利于统计和后台配置；
- 课程设计 Demo 更适合展示确定的业务规则。

每个阶段任务应由以下内容组成：

| 字段 | 说明 |
|---|---|
| 阶段任务名称 | 例如“设计数据库” |
| 任务情境 | 系统展示给用户的具体场景 |
| 任务目标 | 本阶段要解决的问题 |
| 任务类型 | 单选、小游戏、小测、属性判定等 |
| 完成方式 | 系统预设的操作或选择 |
| 结算规则 | 如何计算分数、评价、属性变化 |
| 后续影响 | 是否留下过程标签或影响下一阶段 |

支持的任务类型：

| 类型 | 说明 | 示例 |
|---|---|---|
| 单选策略 | 用户从几个处理方式中选一种 | 需求风暴 |
| 随机事件 | 进入任务后随机触发状况 | 答辩前电脑更新 |
| 判断/小测 | 用于知识类任务 | SQL 主键外键判断 |
| 属性判定 | 根据技能、自律、压力等决定结果 | 高技能降低 Bug 风险 |
| 普通确认 | 不重要阶段点击完成即可 | 领取资料 |
| 关键任务 | 选择、小游戏、属性共同影响结局 | 数据库设计、最终 Bug 修复 |

## 过程标签

过程标签用于记录关键选择和后果。它可以影响后续阶段和最终结局。

示例：

| 标签 | 含义 |
|---|---|
| `scope_controlled` | 需求范围控制得好 |
| `scope_sprawl` | 需求范围失控 |
| `report_first` | 优先补报告，功能推进一般 |
| `schema_clear` | 数据库关系清晰 |
| `schema_shaky` | 数据库关系勉强能用 |
| `schema_mist` | 数据库关系混乱 |

标签用途：

- 调整后续任务得分；
- 改变阶段结果文案；
- 决定是否触发补救任务；
- 影响最终评价；
- 在结算页展示玩家路线。

## Java 课设副本：DDL 前夜

### 副本背景

时间接近课程设计答辩。HAUT Survivor 已经能登录和创建角色，但系统还缺少能体现数据库设计、校园特色和玩法创新的核心内容。用户需要在压力下推进需求、数据库和 Bug 修复。

### 推荐流程

| 顺序 | 阶段 | 情境 | 任务类型 | 核心影响 |
|---|---|---|---|---|
| 1 | 需求风暴 | 老师突然强调系统要体现数据库设计和校园特色 | 单选策略 | 决定需求范围、压力和后续风险 |
| 2 | 数据库拼图 | 表关系混乱，需要串起用户、属性、事件、选项、副本 | 轻量小游戏 | 根据关系选择、用时、技能和前置标签结算 |
| 3 | Bug 暴走 | 答辩前页面或数据突然异常 | 关键任务/后续可改为 Bug 定位小游戏 | 决定最终分数和结局 |

### 阶段 1：需求风暴

情境：

```text
老师提醒：系统不能只是登录、增删改查和几个表格，要体现校园特色、数据库设计和可玩性。
你发现自己原本想做的功能太多，时间却只剩几天。你要如何调整课设目标？
```

选项方向：

| 选项方向 | 评价 | 后果 |
|---|---|---|
| 砍掉花哨功能，聚焦地图、事件、副本主线 | 优秀完成 | 添加 `scope_controlled`，降低后续风险 |
| 继续加很多功能，试图一次做完整 | 勉强完成 | 添加 `scope_sprawl`，后续数据库和 Bug 风险上升 |
| 先写报告，再慢慢补系统 | 普通完成 | 添加 `report_first`，展示风险较低但功能收益一般 |

### 阶段 2：数据库拼图

当前实现形式：勾选正确表关系。

正确关系示例：

- `user -> player_attribute`
- `event -> event_option`
- `dungeon -> dungeon_task`

错误关系示例：

- `user -> event`
- `task -> event_option`
- `campus_location -> player_attribute`

结算因素：

| 因素 | 影响 |
|---|---|
| 正确关系数量 | 增加得分 |
| 错误关系数量 | 扣分 |
| 用时 | 低用时奖励，高用时惩罚 |
| 技能值 | 技能较高时加成 |
| `scope_controlled` | 加成 |
| `scope_sprawl` | 惩罚 |

结算结果：

| 评价 | 条件方向 | 标签 | 后果 |
|---|---|---|---|
| 结构清晰 | 高分 | `schema_clear` | 技能、自律提升，压力下降 |
| 勉强能用 | 中分 | `schema_shaky` | 小幅提升，压力略增 |
| 表关系迷雾 | 低分 | `schema_mist` | 压力增加，最终结局受影响 |

### 阶段 3：Bug 暴走

当前版本：单选关键任务。

下一步建议升级为真正 Bug 定位小游戏：

```text
系统展示 3-5 条简化报错或异常现象。
用户选择最可能原因。
系统根据选择、技能值、压力值、数据库拼图结果结算。
```

候选题：

| 现象 | 正确原因 |
|---|---|
| 提交事件选项后 404 | Controller 路径或表单 action 不一致 |
| 数据库字段读出来为空 | 实体字段和数据库列映射不一致 |
| Mapper 无法注入 | Mapper 扫描或注解缺失 |
| 启动失败提示 8080 被占用 | 旧进程未关闭 |
| 外键相关数据查不到 | 表关系设计或查询条件错误 |

## 副本结局

Java 课设副本结局示例：

| 结局 | 条件方向 | 文案方向 |
|---|---|---|
| 课设战神 | 总分高，`scope_controlled`，`schema_clear` | 课设结构清楚，答辩有底气 |
| DDL 幸存者 | 总分中高，部分阶段普通 | 最后赶上了，但过程很惊险 |
| 勉强过关 | 总分一般，存在明显短板 | 能演示，但答辩需要解释 |
| 答辩沉默现场 | 分数低或 `schema_mist` 严重 | 面对老师追问陷入沉默 |
